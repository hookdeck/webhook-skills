# Setting Up Spike API Webhooks

## Prerequisites

- A Spike API application with access to the Spike API admin console
- A publicly reachable HTTPS endpoint (use the Hookdeck CLI for local development)

## Get Your Webhook Signature Key

Spike API signs every delivery with the application's **Webhook Signature Key**,
generated by Spike API and shown in the admin console under your application
settings. It is not the **HMAC Key** on the same screen, which signs user IDs for
authentication, even though Spike's code samples name the constant
`HMAC_KEY_FROM_ADMIN_CONSOLE`. Store it as `SPIKE_API_WEBHOOK_SECRET` and use it
exactly as shown (UTF-8 string); do not hex- or base64-decode it.

## Register Your Endpoint

1. Open the Spike API admin console.
2. Set the **Main Webhook URL** for your application. The separate Lab Reports and
   Nutrition Records webhook URLs receive those products' async results, which have a
   different payload shape and are not covered by this skill.
3. For local development, run `npx hookdeck-cli listen 3000 spike-api --path /webhooks/spike-api` and use the printed URL.

Spike API sends `record_change`, `provider_integration_created` and
`provider_integration_deleted` events to the Main Webhook URL. There is no
per-event subscription to choose.

## Testing

Trigger a real data update or provider connection for a test user and inspect the
delivery. Because every request is signed, send test requests with a locally
computed `X-Body-Signature` (see [verification.md](verification.md)).

## Hookdeck

Hookdeck's Spike API source verifies the signature before forwarding to your handler.
