# Setting Up ZITADEL Webhooks

> Only Actions v2 targets with the JSON payload type are supported. JWT and JWE payload types aren't.

## Prerequisites

- A ZITADEL instance (cloud or self-hosted) and a user with at least the `IAM_OWNER` role
- A token for the ZITADEL API
- Your application's webhook endpoint URL (use a Hookdeck URL for local development)

## Get Your Signing Secret

The signing key is generated per target and returned **when you create the target**:

```bash
curl -L -X POST "https://${CUSTOM_DOMAIN}/v2/actions/targets" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer <TOKEN>" \
  --data-raw '{
    "name": "my webhook",
    "restWebhook": { "interruptOnError": true },
    "endpoint": "https://your-endpoint.example.com/webhooks/zitadel",
    "timeout": "10s",
    "payloadType": "PAYLOAD_TYPE_JSON"
  }'
```

```json
{ "id": "344649040681500814", "creationDate": "2025-10-31T15:00:36.432595Z", "signingKey": "somekey" }
```

Save `signingKey` as `ZITADEL_WEBHOOK_SECRET`. It can be regenerated by patching the target. Set `payloadType` explicitly to `PAYLOAD_TYPE_JSON`, as the ZITADEL examples do. JWT and JWE targets don't use this key.

## Register Your Endpoint

Link the target to a condition with an execution. For an event:

```bash
curl -L -X PUT "https://${CUSTOM_DOMAIN}/v2/actions/executions" \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer <TOKEN>" \
  --data-raw '{
    "condition": { "event": { "event": "user.human.added" } },
    "targets": ["<TargetID returned>"]
  }'
```

Other conditions: `{"request": {"method": "/zitadel.user.v2.UserService/CreateUser"}}`, `{"response": {...}}` and `{"function": {"name": "preuserinfo"}}`.

## Test

Create a user in the Management Console or through `POST /v2/users/new` and watch the request arrive.

## Using Hookdeck

1. Create a Hookdeck source of type `ZITADEL` and paste the target's `signingKey` as the signing secret.
2. Use the Hookdeck source URL as the target's `endpoint`.
3. Locally: `npx hookdeck-cli listen 3000 zitadel --path /webhooks/zitadel`

Hookdeck's source verifies the signature. Only Actions v2 targets with the JSON payload type are supported. JWT and JWE payload types aren't.
