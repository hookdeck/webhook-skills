# Uphold Webhooks Overview

## What Are Uphold Webhooks?

Uphold Enterprise's REST APIs send webhooks so you learn about platform changes in near real time, without polling: a user passing KYC, a deposit settling, a card being declined. Each group of Core API endpoints (Users, KYC, KYB, Accounts, External accounts, Transactions, Assets) has its own events. You subscribe per event type in the Webhooks Portal.

Delivery is handled by [Svix](https://www.svix.com/) under Uphold's name. Headers are `Webhook-Id`, `Webhook-Timestamp` and `Webhook-Signature`, signatures follow Svix's scheme, and retries follow Svix's schedule.

## What Does an Uphold Webhook Event Look Like?

Every event has the same envelope:

```json
{
  "id": "6a3d8cea-5250-4bd0-a443-eb07b04c85d4",
  "type": "core.user.created",
  "createdAt": "2025-02-20T21:21:09.943Z",
  "data": {}
}
```

| Field | Meaning |
|-------|---------|
| `id` | Uphold's event id (UUID) |
| `type` | Event type, `<api>.<resource>.<action>` |
| `createdAt` | When Uphold created the event (ISO 8601) |
| `data` | Event-specific payload |

`id` and `createdAt` are generated by Uphold. The `Webhook-Id` and `Webhook-Timestamp` headers are generated by Svix and are scoped to a delivery. Use the headers for signature verification and the payload fields for business logic.

> Uphold's webhooks page shows `"type": "core.users.created"` in its envelope example. The actual event name is `core.user.created` (singular), as used in the event reference and the OpenAPI spec. Likewise, the spec's sample payload for the balance event shows `core.account.balance.changed`, but the subscribable event is `core.account.balance-changed`. Match on the names in the tables below.

## Common Event Types

| Event | Triggered When | Common Use Cases |
|-------|----------------|------------------|
| `core.user.created` | A new user has been created | Provision the user in your system |
| `core.transaction.status-changed` | A transaction's status changed (`processing`, `on-hold`, `completed`, `failed`) | Credit funds on `completed`; alert on `failed` or `on-hold` |
| `core.transaction.created` | A new transaction has been created | Show a pending transfer in your UI |
| `core.account.balance-changed` | The balance of an account has changed | Refresh displayed balances |
| `core.external-account.status-changed` | A linked card, bank, APM or crypto account changed status | Prompt the user to re-link a failed card |
| `core.kyc.identity.status-changed` | The identity KYC process changed status | Unlock features when `ok` |
| `core.kyb.profile.status-changed` | A business's KYB profile process changed status | Business onboarding |

## Example: `core.transaction.status-changed`

```json
{
  "id": "123e4567-e89b-12d3-a456-426614174000",
  "type": "core.transaction.status-changed",
  "createdAt": "2021-01-01T00:00:00.000Z",
  "data": {
    "transaction": {
      "id": "623000c8-9bdf-4a2b-aa3d-6a6b44a7f6a0",
      "origin": {
        "amount": "100.00", "asset": "GBP", "rate": "47619.04761904762",
        "node": { "type": "account", "id": "b98e4f0d-...", "ownerId": "e4ce04dc-..." }
      },
      "destination": {
        "amount": "0.0021", "asset": "BTC", "rate": "0.000021",
        "node": { "type": "account", "id": "555a99a1-...", "ownerId": "e4ce04dc-..." }
      },
      "denomination": { "amount": "100.00", "asset": "GBP", "target": "origin", "rate": "1" },
      "fees": [],
      "status": "completed",
      "quotedAt": "2024-07-24T15:02:39.000Z",
      "createdAt": "2024-07-24T15:22:39.000Z",
      "updatedAt": "2024-07-24T15:32:39.000Z"
    }
  }
}
```

Amounts are decimal **strings**. Keep them as strings or use a decimal library, never floats. `node.type` can be `account`, `external-account`, `apm`, `bank-address` or `crypto-address`.

## How Are Uphold Webhooks Delivered and Retried?

- A delivery fails on a non-2xx response or a timeout. Failed deliveries are retried with exponential backoff, starting with short intervals, **for up to 24 hours** or until one succeeds ([Svix retry schedule](https://docs.svix.com/retries)).
- You can redeliver manually from the Enterprise Portal (Webhooks section) or the Webhooks Portal.
- Delivery is at least once. Retries keep the same `Webhook-Id` and payload `id`, so dedupe on either one.
- Respond with a `2xx` quickly and do slow work asynchronously.
