# How to Verify Deck Webhook Signatures

## How Does Deck Sign Webhooks?

Deck signs every `webhook` destination delivery with the [Standard Webhooks](https://www.standardwebhooks.com/) specification:

| Header | Description |
|--------|-------------|
| `webhook-id` | Unique event identifier |
| `webhook-timestamp` | Unix timestamp (seconds) of when the delivery was sent |
| `webhook-signature` | `v1,<base64 HMAC-SHA256>`. Under the spec this can hold several space-separated `v1,...` entries |

- **Algorithm:** HMAC-SHA256, base64-encoded
- **Signed content:** `{webhook-id}.{webhook-timestamp}.{raw body}`
- **Key:** the bytes you get by base64-**decoding** the part of the secret after `whsec_`
- **Secret:** generated by **you** and supplied as `webhook.secret` when you create the destination. Deck doesn't issue one, and it can't be read back (see [setup.md](setup.md))

## Why Does Signature Verification Matter?

Your webhook URL is public. Without verification, anyone can POST a fake `task_run.completed` or `credential.verified` and drive your workflows. The timestamp check also stops replays of captured deliveries.

## SDK Verification (Recommended)

Deck's docs say to use the official Standard Webhooks SDK, which handles timestamp tolerance (±5 minutes), multiple signatures and constant-time comparison.

### Node.js (`standardwebhooks` on npm)

```javascript
const { Webhook } = require('standardwebhooks');

const wh = new Webhook(process.env.DECK_WEBHOOK_SECRET); // "whsec_..." accepted as-is

// rawBody: string or Buffer of the EXACT bytes received
// headers: any object containing webhook-id / webhook-timestamp / webhook-signature
const event = wh.verify(rawBody, headers); // returns parsed JSON or throws WebhookVerificationError
```

- Express: `express.raw({ type: '*/*' })` on the route, then pass `req.body` (a Buffer).
- Next.js App Router: `const rawBody = await request.text()`.

### Python (`standardwebhooks` on PyPI)

```python
from standardwebhooks.webhooks import Webhook

wh = Webhook(os.environ["DECK_WEBHOOK_SECRET"])
event = wh.verify(await request.body(), {
    "webhook-id": request.headers.get("webhook-id"),
    "webhook-timestamp": request.headers.get("webhook-timestamp"),
    "webhook-signature": request.headers.get("webhook-signature"),
})  # raises WebhookVerificationError (or ValueError / binascii.Error on malformed input)
```

The Python SDK raises errors other than `WebhookVerificationError` for malformed input (for example a signature entry without a comma, or invalid base64). Catch `Exception` around `verify()` and return `400`.

### Secret Rotation: Verify Against Both Secrets

Deck keeps the previous secret valid for **24 hours** after a rotation, so during that window you may receive deliveries signed with either secret. Try each configured secret and accept the first that verifies:

```javascript
function verifyDeckWebhook(rawBody, headers) {
  const secrets = [process.env.DECK_WEBHOOK_SECRET, process.env.DECK_WEBHOOK_SECRET_PREVIOUS].filter(Boolean);
  let lastError = new Error('No signing secret configured');
  for (const secret of secrets) {
    try {
      return new Webhook(secret).verify(rawBody, headers);
    } catch (err) {
      lastError = err;
    }
  }
  throw lastError;
}
```

## Manual Verification (Reference)

You don't need this in Node.js or Python because the SDK covers both. It's here for languages without an SDK and for debugging.

### Node.js

```javascript
const crypto = require('crypto');

function verifyDeckSignature(rawBody, headers, secret, toleranceSeconds = 300) {
  const id = headers['webhook-id'];
  const timestamp = headers['webhook-timestamp'];
  const signatureHeader = headers['webhook-signature'];
  if (!id || !timestamp || !signatureHeader) return false;

  const ts = parseInt(timestamp, 10);
  if (Number.isNaN(ts) || Math.abs(Math.floor(Date.now() / 1000) - ts) > toleranceSeconds) return false;

  const key = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const expected = crypto
    .createHmac('sha256', key)
    .update(`${id}.${timestamp}.${rawBody}`) // rawBody as received
    .digest('base64');

  return signatureHeader.split(' ').some((entry) => {
    const [version, sig] = entry.split(',');
    if (version !== 'v1' || !sig) return false;
    const a = Buffer.from(sig);
    const b = Buffer.from(expected);
    return a.length === b.length && crypto.timingSafeEqual(a, b);
  });
}
```

### Python

```python
import base64, hashlib, hmac, time

def verify_deck_signature(raw_body: bytes, headers, secret: str, tolerance: int = 300) -> bool:
    msg_id = headers.get("webhook-id")
    timestamp = headers.get("webhook-timestamp")
    signature_header = headers.get("webhook-signature")
    if not (msg_id and timestamp and signature_header):
        return False
    try:
        if abs(int(time.time()) - int(timestamp)) > tolerance:
            return False
    except ValueError:
        return False

    key = base64.b64decode(secret.removeprefix("whsec_"))
    signed = f"{msg_id}.{timestamp}.".encode() + raw_body
    expected = base64.b64encode(hmac.new(key, signed, hashlib.sha256).digest()).decode()

    for entry in signature_header.split(" "):
        version, _, sig = entry.partition(",")
        if version == "v1" and hmac.compare_digest(sig, expected):
            return True
    return False
```

## Common Gotchas

- **Parsed or re-serialised body.** `express.json()`, `request.json()` or a Pydantic body model changes whitespace and key order, so the HMAC won't match. Verify the raw bytes first and parse afterwards.
- **Using the secret string as the HMAC key.** The key is `base64decode(secret without "whsec_")`, not the literal string. The SDK does this for you. In manual code it's the most common bug.
- **No secret on the destination.** If the destination was created without `webhook.secret`, there's nothing to verify against. Set one (see [setup.md](setup.md)). Don't skip verification.
- **Lost secret.** Deck can't return it. Generate a new one and set it on the destination.
- **Fail closed.** If `DECK_WEBHOOK_SECRET` isn't set, return `500` and reject the delivery. Never fall through to "accept".
- **Clock skew.** The SDK rejects timestamps more than 5 minutes from your server clock. Keep NTP running.
- **Only checking the first signature.** `webhook-signature` can contain several space-separated `v1,...` entries. Accept the delivery if any entry matches.
- **Non-constant-time comparison.** Use `crypto.timingSafeEqual` / `hmac.compare_digest` (the SDK already does).
- **Status codes.** Return `400` (or `401`, as Deck's own sample does) for bad signatures. Deck retries any non-`2xx` up to 10 times, which is harmless for forged requests.

## How to Debug Verification Failures

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Every delivery fails | Secret in `.env` doesn't match the one sent to Deck, or the key isn't base64-decoded | Generate a new secret, set it on the destination and in `.env` |
| Every delivery fails after a deploy | Body parser added before the webhook route | Mount the raw body parser on the webhook route only |
| `Message timestamp too old` | Server clock skew, or replaying an old captured request | Fix NTP. Re-sign when replaying in tests |
| `Missing required headers` | Proxy stripping `webhook-*` headers, or a non-Deck caller | Check proxy and CDN header forwarding |
| Failures only during a rotation | Previous secret not configured | Set `DECK_WEBHOOK_SECRET_PREVIOUS` for 24 hours |
| Destination stuck in `pending_verification` | Endpoint unreachable or returning non-`2xx` | Check the URL, TLS and route path, and that the secret is configured on the server |

When debugging locally, `npx hookdeck-cli listen 3000 deck --path /webhooks/deck` shows the exact headers and body of each request. Replays more than 5 minutes after the original delivery fail the timestamp check, which is expected.
